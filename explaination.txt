This demonstration project for BCS703 (Cryptography and Network Security) implements a local SHA-256 file integrity verification suite inside the cns_hash_demo directory using Python's standard library. Four dummy text files were created: sample.txt containing the 25-byte string "This is a CNS lab sample.", an identical copy sample_copy.txt, a tampered copy sample_tampered.txt where only one letter was changed ("lab" to "Lab", flipping a single ASCII bit from 0x6C to 0x4C), and a larger 5200-byte file sample_big.txt containing repeated lines of the dummy text. The Python script hash_demo.py reads files in 4096-byte binary chunks and uses SHA-256, a one-way cryptographic hash function that deterministically maps inputs of any length to a fixed 256-bit (64-hexadecimal-character) digest with a strong avalanche effect. In the executed run, sample.txt and sample_copy.txt both produced the identical hash 8bb20bacc7507165142b144e3d7c327347393548f8002884136cc0b549a3d522 (passing the normal-match test), while sample_tampered.txt produced ca815d8914c5c56b550e7e572a27894b4253dcb44fc68abe3ecda042ca046c8f (passing the tamper-detection test). Storing the original digest in sample.txt.sha256 and calling verify_file returned OK on sample.txt and INTEGRITY FAILED on sample_tampered.txt, while comparing the two hashes revealed the avalanche effect with 61 of 64 hex characters (95.31%) and 127 of 256 bits (49.61%) differing from a single-bit edit. Furthermore, sample_big.txt produced the 64-character digest 5f13aa4c6585e19ff1af6f8e365b7ccfa9123a935541bb3fce15cf8a67ea0ac5 confirming fixed output length, three consecutive hashes of sample.txt matched identically confirming determinism, Windows PowerShell's Get-FileHash -Algorithm SHA256 matched Python's digests identically (while OpenSSL commands were skipped because OpenSSL is not installed on this machine), and the bonus HMAC-SHA256 demo with the fake key "demo-key-not-real" and constant-time hmac.compare_digest produced distinct tags (c9c95c63951ae8be200292c6c1b09b1d3987a9f511921813837852d2e6f07402 for sample.txt versus 46186b53275509222c02dd25720dde4aeb60f03c92c1c5e63edb71bcd520f2bc for sample_tampered.txt).

These results prove that SHA-256 reliably guarantees file integrity by detecting both accidental corruption and intentional modification down to a single changed bit, while demonstrating the fundamental difference between hashing and encryption: hashing is a keyless, one-way transformation designed for integrity verification rather than hiding data, whereas encryption is a reversible, key-dependent transformation designed for confidentiality so authorized parties can recover the original plaintext. In practical cybersecurity workflows, this property gives a clear benefit when verifying downloaded software installers, backups, and forensic images against published checksums so corrupted or altered files are rejected before use. However, a plain unkeyed SHA-256 hash also has an important limitation because it does not prove authentication or origin: since anyone can compute a SHA-256 digest, an attacker who intercepts and modifies a file can simply recalculate and replace the accompanying .sha256 checksum file as well, meaning keyed Message Authentication Codes such as HMAC or asymmetric digital signatures are needed whenever sender authenticity and tamper resistance against active attackers are required. All testing in this project was performed strictly in accordance with lab safety rules using only harmless dummy text inside the local cns_hash_demo folder, with zero network access, zero external installs, and no real credentials, secrets, or personal data.
